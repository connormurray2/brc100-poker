# Gate e: the on-chain evaluator

Status: **PASS** (2026-10-30).

A Rúnar contract, `Eval7`, scores seven cards on chain as the best five-card hand. It accepted the score of
the TypeScript reference, `bestScore`, for **all 2,000 vectors** of a corpus scored by the Go evaluator
(`internal/game/eval`), and it rejected a claimed score one too low or one too high in every category. At
showdown the dispute referee runs this evaluator, so agreement with Go is what keeps a payout right.

Every evaluation is a real `@bsv/sdk` `Spend` of the compiled script (MockProvider, input validated):
`contracts/test/gate-e.test.ts`. Rúnar's own interpreter is not used.

## What was built

- `contracts/src/Eval7.runar.ts`, generated by `contracts/gen/gen-eval7.py` (`python3 contracts/gen/gen-eval7.py`).
  It is straight-line code with no loops: rc.1's codegen mishandled mutable locals inside unrolled loops. No
  local is named `t<digits>` (icellan/runar#175).
- `check(a, b, c, d, e, f, g, expected)` asserts that each card is in `0..51` and that the evaluated score equals
  `expected`. It is stateless.
- Card `i` has rank `i / 4` (0 = deuce .. 12 = ace) and suit `i % 4`, which is `cards.Card.Index()`.
- Score = `category · 16⁵ + five tiebreak values` (rank + 1, 0 = none), in base 16. Categories 0..8 are
  high card, pair, two pair, trips, straight, flush, full house, quads, straight flush.
- `packages/protocol/src/eval.ts` has `bestScore`, the best of all 21 five-card subsets in that encoding. It is
  independent of the contract's code.
- `scripts/gates/evalvectors` writes the corpus from `eval.Best`, and
  `packages/protocol/test/fixtures/eval-vectors.json` is the checked-in copy, read by both test suites.

## Is the encoding the same as Go's?

Not number for number. Go's `Score` stores the rank itself (2..14) and zero-fills; the contract stores rank + 1
(0 = none). Both keep the same categories, in the same order, with `Category` running `HighCard = iota ..
StraightFlush` (9 values, 0..8) as the contract's 0..8, and both order hands the same way. The tests therefore
compare **category equality and the sign of every score difference**, not the scores. Go's top score in the
corpus is 9,306,112; both fit comfortably in a script number.

## Corpus

2,000 distinct seven-card hands, from `go run ./scripts/gates/evalvectors -n 2000 -seed 1`:

| Category | Vectors |
|---|---|
| 0 high card | 348 |
| 1 pair | 809 |
| 2 two pair | 439 |
| 3 trips | 102 |
| 4 straight | 102 |
| 5 flush | 80 |
| 6 full house | 68 |
| 7 quads | 27 |
| 8 straight flush | 25 |

- **A fixed set of 32 hands**, which includes the plan's Review Focus 4 hands:
  - the wheel (A-2-3-4-5), with and without a six;
  - two trips (low set dealt first, and last), and trips with two pairs;
  - three pairs, where the kicker comes from the third pair or from outside;
  - six- and seven-card flushes, including one that leaves the best offsuit card out;
  - two steel wheels, a royal flush, a straight flush inside a longer straight, and a flush that is also a straight;
  - quads with a trips kicker available;
  - board-plays ties: a straight board, a royal board, a full-house board and an ace-high board, each with two
    different pairs of hole cards that must score the same.
- **Rare categories topped up** by seeded rejection sampling to at least 25 vectors each.
- **Seeded random hands** for the rest. The whole corpus is shuffled by the seed, so neighbouring vectors are
  unrelated.

## Checks

| Test | Result |
|---|---|
| `packages/protocol/test/eval.test.ts`: `bestScore` has Go's category on every vector, and `sign(bestScore(a) − bestScore(b))` equals `sign(scoreA − scoreB)` for every consecutive pair | pass |
| the same sign agreement for **every pair within each category** (all pairs of each bucket, about 500,000) | pass |
| `gate-e`: the compiled evaluator accepts `bestScore` for every vector | pass, 2,000 of 2,000 |
| `gate-e`: `bestScore − 1` and `bestScore + 1` are rejected, one vector per category | pass, 9 categories |
| `gate-e`: a card index of 52 or −1 is rejected | pass |

Breaking the wheel rule in `bestScore` (five-high straight scored as ace-high) makes both agreement tests fail.

## The Rúnar miscompile

On the vendored build before this gate (`main` at `d207ee8e`) the evaluator **failed on the first hand**, quad 2s
with ace, king and queen kickers: a branch arm reordered the slots it inherits and a later read took its neighbour
(icellan/runar#178). The vendored compiler is now `main` plus the #179 and #177 fix branches; see
`contracts/vendor/runar/PROVENANCE.md` (heads `9fb51ea5` and `b96bc8fc`, merge `cb34fd26`). This gate passes only on
that build. If the vendored build is ever moved back to a Rúnar without #179, run this suite first.

The rejection tests pass on both builds, so they prove nothing about the fix. The acceptance test is what does.

## Limits to carry into the referee

- **Duplicate cards are not rejected on chain.** `check` asserts only that each index is in `0..51`. A hand with the
  same card twice is scored as if it were legal. The referee must tie each card to a proven, distinct deck position
  before it calls `check`. `bestScore` throws on duplicates and Go does not check either.
- **The evaluator takes seven cards.** A hand evaluated from five or six cards (all-in before the river) needs
  another entry point or padding rules; not built here.
- **Not broadcast.** This is `Spend` on MockProvider, as for gate (d). It is gate (a) that sends scripts to a node.

## Verdict

**PASS.** The compiled evaluator and the Go evaluator agree on category and ordering for 2,000 hands, including the
cases where evaluators diverge, on a Rúnar build that carries the #178 fix.
